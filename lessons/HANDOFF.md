# 交接包：广东 3+证书数学 · 302 条知识点讲义

> 给接收方 agent 看的说明。读完这一页就能直接用，不需要再回看生成过程。

## 一、这是什么

`cs-math-skill-tree` 里 302 条知识点（原来每条只有一个标题，平均 12 字）已逐条扩写成四段讲解。内容按领域组织成可直接执行的 JS，标题与 `data.js` 的 `SKILLS[].pts` 原文逐字一致。

## 二、文件

| 文件 | 用途 |
|---|---|
| `lessons/lessons.all.js` | **主交付物**。11 个 `LESSONS_<领域>` 常量 + `LESSONS_ALL` + `LESSONS_BY_SKILL`，头部注释即数据契约 |
| `lessons/prep.js` … `lessons/cplx.js` | 按领域拆开的源文件，内容与主文件一致，便于单独更新某个领域 |
| `lessons/HANDOFF.md` | 本说明 |

## 三、数据结构

```js
LESSONS_FUNC = {
  f1: [
    { t: '函数三要素与记号 f(x)', body: '一、这是什么 …… 二、怎么做 …… 三、容易错在哪 …… 四、一个小例子 ……' },
    ...
  ],
  ...
}
```

- 键：技能 id（与 `data.js` 的 `SKILLS[].id` 一致，共 110 个技能）。
- `t`：知识点标题，**必须与 `pts` 原文一字不差**（含全角标点、上下标、空格）。
- `body`：单个字符串，四段用段首固定词分隔，段内不换行。
- 聚合：`LESSONS_ALL[领域id][技能id]`；`LESSONS_BY_SKILL[技能id]`（已拍平）。

## 四、硬约束（改动前先读）

1. 不要改写 `t`，不要重排条目顺序去对齐别的数据源——以 `data.js` 的 `pts` 为准。
2. `body` 不要拆成数组、不要改段名（四个段首词是校验依据）。
3. 每条含小标题 150~250 字；补写也要守住这个区间。
4. 不写空话，不抄题干；数学结论拿不准就标「存疑」，不要编。
5. 新增或修改后要重跑校验（见第六节），不能只看条数。
6. 若接收方手上没有 `data.js`，就以文件内的 `t` 为准，不要另造标题或改写措辞。

## 五、覆盖与已知问题

- 覆盖：**302/302**（prep26 set16 ineq19 func25 explog24 trig36 seq27 vec23 geo51 prob41 cplx14），110 个技能全覆盖。
- 规模：正文 60,614 字，平均 201 字/条。
- 存疑 1 条：`prob r12`「第 p 百分位数」——`i=np%` 为整数时，取第 i 个还是取第 i、i+1 个的平均，各教材取法不同；正文已注明「以本校教材为准」，接入时不要替它选定一种。
- 校验已过：标题逐字匹配、四段齐全、字数区间、无重复正文、`node --check` 语法通过。

## 六、接入与验收

浏览器：

```html
<script src="lessons/lessons.all.js"></script>
<script>const pts = LESSONS_FUNC.f1; // 按技能取讲义</script>
```

Node / 构建脚本：

```js
const { LESSONS_ALL, LESSONS_BY_SKILL } = require('./lessons/lessons.all.js');
```

验收脚本要点（缺一不可）：

1. 用 `data.js` 的 `SKILLS` 逐条比对 `t`，必须 302 条全部命中；
2. 每条 `body` 含四个段首词；
3. 去空白后字数在 150~250；
4. 没有两条 `body` 完全相同。

## 七、可直接转发的指令

> 你接手一份数学讲义交接包，路径 `lessons/lessons.all.js`，说明见 `lessons/HANDOFF.md`。
> 任务：把它接进 `cs-math-skill-tree`，让每个知识点在技能卡片里显示对应 `body`（四段）。
> 约束：`t` 必须与 `data.js` 的 `pts` 原文一字不差，不要改写；`body` 不要拆段、不要重写段名；不要新增无内容占位条目。
> 验收：按 HANDOFF 第六节的四条脚本化检查跑一遍，报「302/302 命中、四段齐全、字数合规、无重复」才算完成；`prob r12` 的存疑保持原样，不要自行选定取法。
